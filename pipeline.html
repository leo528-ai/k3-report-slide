Kimi K3 · 原生多模态视觉训练

图像训练数据流拆解
以一张胸片为例

实例样本：一张 896×896 的胸部 X 光片，配一句标注文字「双肺纹理增多」。
训练目标：给定这张片子，让模型逐字预测出「双肺纹理增多」——没有任何单独的视觉标签。
■ 报告真实设定：token 数关系、pixel-shuffle 压到 1/4、27 层、最大 3584×3584、从零 NTP 训练。 ■ 示意值：patch=14×14、ViT 维=1152、主干维=7168（报告未直接给出，仅为把数字走通）。
1

原图 → 张量

[896, 896, 3] # 高 × 宽 × RGB
↓切成 14×14 的小方块
2

切 patch

每边 896/14 = 64 个，全图 64×64 = 4096 个 patch；每个拉平 14×14×3 = 588 维。
[4096, 588] # 4096 个 patch
↓linear projection
3

线性投影进 ViT

[4096, 588] ─▶ [4096, 1152] # 4096 个视觉 token
↓27 层空间注意力
4

MoonViT-V2 编码27 层 · ~0.4B

静态图只走「帧内空间注意力」一趟；视频才多走「帧间时间注意力」+ 时间池化。图像视频共享参数。
[4096, 1152] ─27层─▶ [4096, 1152]
↓2×2 pixel-shuffle
5

pixel-shuffle 2×2　关键：token 砍到 1/4

相邻 2×2 的 4 个 token 合并成 1 个：token 数 ÷4，维度 ×4。这一步让大图"吃得下"1M 上下文。
[4096, 1152] ─▶ [1024, 4608] # 4096/4=1024, 1152×4=4608
↓MLP projector
6

MLP 投影器 → 共享空间

映射到和文字 token 同一维度、同一空间——从此视觉和文字是"同一种货币"。
[1024, 4608] ─▶ [1024, 7168] # 这张胸片 = 1024 个 token
换成最大的 3584×3584：256×256=65536 patch → shuffle 后 16384 token。
↓和文字拼接
7

拼成一条序列

「双肺纹理增多」= 6 个文字 token，接在 1024 个视觉 token 后面。图像 token 不算 loss，但它们是"上文"。
v₁图 v₂图 …… v₁₀₂₄图 双✓loss 肺✓loss 纹✓loss 理✓loss 增✓loss 多✓loss
↓走到位置 1027，预测下一个字
8

预测 + 算 loss

已看过 1024 图 + "双""肺"，预测第 1028 个字。真实答案 = 纹理。
纹理0.55
炎症0.20
结节0.10
loss = −log(0.55) ≈ 0.60
↓反向传播
9
文字预测 loss ─▶ 主干 ─▶ MLP 投影器 ─▶ pixel-shuffle ─▶ MoonViT-V2 (27 层)
为了把「纹理」预测得更准，梯度会去调整对应肺纹理区域的视觉 token（v₃₈₀、v₄₀₁…）的编码。也就是——"看懂肺纹理"是被"预测出'纹理'这个字"逼出来的，全程没有单独的视觉标签。这就是原生 NTP 训练视觉的本质。
训练系统侧：这么多 token 怎么算得起
动态上下文并行 CP
3584 大图有 16384 token，单卡吃不下 → 沿 patch 维切开分到多卡，注意力时 gather-KV 收齐；多张大图再拆 sub-CP 组做负载均衡。
编码器藏进流水线气泡
主干流水线并行天然有空泡 → 沿用 K2.5 的 DEP，把 ViT 前向/反向拆碎塞进 interleaved-1F1B 的空泡里，额外耗时基本抹平。
一句话记住：896×896 → 4096 patch → 27 层编码 → shuffle 到 1024 token → 投影进主干 → 接 6 个文字 token → 在文字位置算 loss → 梯度回传，把"看懂肺纹理"教给视觉编码器。训练系统再用动态 CP 切大图、把编码器藏进流水线气泡扛住成本。
