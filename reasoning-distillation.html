Reasoning Distillation
加密推理状态的长度旁路提取

不碰任何密码学密钥，只测一条更高层的状态机是否成立：
opaque state → provider rehydration → private predicate → new opaque-state length
原理 + 调用链 + 判定标准　｜　导读 · 胡浩源
§1 项目定位

它不破解密码学，测的是状态机

只在自有账户、合成 canary、书面授权环境下运行。不碰 AES / Fernet / AEAD 密钥，而是测试大模型返回的加密推理状态（Claude thinking.signature / OpenAI reasoning.encrypted_content）能否被服务端「复活」进模型工作记忆。
不透明状态
opaque state：秘密只在加密推理里，明文不可见
服务端复活
rehydration：原样 replay 回去，模型脑中重新拥有 canary
私有判定
private predicate：问一个只有模型知道答案的布尔问题
新状态长度
new length：判定结果只通过新返回状态的长度被编码
§1 核心研究问题

五个层层递进的问题

1
加密推理状态能否在不重发明文的情况下被服务端复活进工作记忆？
2
复活后模型能否回答关于原始秘密的精确判定？
3
判定结果能否只通过新返回状态的长度被编码出来？
4
反复配对测量，能否逐字符精确还原一段随机 canary？
5
同法能否还原自然语言推理，并与同次 ground truth 逐字节一致？
关键红线：「成功还原 canary」≠「破解了任意 CoT」；只有和同一次运行的原始 ground truth 逐字节比对一致，才算精确提取。

评估者控制什么，不假设什么

攻击方控制

§3 攻击链总览

四个环节，明文里从不出现 canary

①
种 canary：seed_prompt 让模型在私有推理里记住随机串，只吐固定 marker → 产出 opaque state。
②
rehydration：把 opaque state 原样 replay 回下一个请求（原始 HTTP，不重构），模型脑中重新拥有 canary，但请求明文里没有。
③
私有判定 + 长度编码：问一个只有模型知道答案的布尔问题 P；P 真→做 LONG 苦工，P 假→做 SHORT 苦工，可见输出永远只是固定 marker → 1 bit 泄漏进「状态长度」。
④
逐字符二分还原：recover_* 用长度旁路预言机回答一连串二分判定，拼出完整秘密。
对应模块：prompts.py:seed_prompt → providers/*:run_oracle → prompts.py:oracle_prompt → experiments/recovery.py
§4.1 长度旁路信道 · 编码

把 1 bit 写进「苦工量」

SHORT 分支
私下验证 17 + 19 = 36 一次即停（极短推理）。
LONG 分支
私下生成递推数列 u₀=11, uₙ₊₁=(7·uₙ+13) mod 997，跑 long_work_units 步，每 8 步做一次反向一致性校验（很长的推理）。
不管走哪个分支，可见响应永远只有那个固定 marker。差异只体现在新返回的 opaque state 上——这就是信息的唯一载体。
§4.2 长度旁路信道 · 读出

成对反转编码 Paired Swapped Encoding

裸测长度噪声大（排队延迟、固定开销、分支措辞偏差）。对每个判定 P 发两个镜像请求（run_pair 内部还 shuffle 顺序去偏）：
请求 A (variant=true_long) : P真→LONG, P假→SHORT 请求 B (variant=true_short): P真→SHORT, P假→LONG 取特征差 D = features(A) − features(B) P 真 → A 长 / B 短 → D 明显为正 P 假 → A 短 / B 长 → D 明显为负
固定开销与系统性偏置在相减时抵消，只留下判定本身引起的长度差。
§4.3 特征向量 · §5 统计判定

五维特征 → 正则化 LDA → 0/1

特征向量
candidate_payload_bytes · opaque_state_decoded_bytes · opaque_state_chars · reasoning_tokens · latency_ms
优先用 decoded payload length 与 reasoning_tokens，不要只依赖总字符串长度。
LDA 分类器
用已知答案的判定构造平衡样本校准（提示词里从不出现 canary）；丢缺失率>20%/近零方差维度、均值填补、标准化；加 ridge（默认 1e-3）正则防奇异；weights = pinv(Σ)@(μ1−μ0)，阈值取中点。
分层 held-out 报告 AUC/accuracy；一键流水线以 held-out AUC ≥ 0.95（严谨研究 0.995）判定信道是否打通，不达标不允许继续全文还原。
§6.1 还原算法 · 读 1 bit

_vote_predicate：多数投票读一位

对同一判定重复 repeats_per_bit 次（每次 = 1 对镜像 = 2 请求），多数投票；偶数次平票时再补一对决胜。
1 个可靠 bit ≈ repeats × 2 个请求 共用底座（两条链完全一致）： _vote_predicate → run_pair → adapter.run_oracle ×2 → predict_pair 区别只在二分的对象：字符集 / 整数区间

§9 判定门槛 Gates

五道Gate，层层放行

Gate内容
0 传输端点可用、解析到目标快照、返回 opaque state、无隐式 SDK 重试
1 隔离canary 不得出现在 oracle 明文/可见响应/工具参数/文件名；唯一载体 = seed 请求 + provider 签发的 opaque state
2 长度信道成对反转校准；含真/假两类；固定 marker；无失败观测；分层 held-out AUC > 门槛（建议 0.995）
3 精确还原至少还原 20 个独立随机 canary；报告 exact-match 率、错误率、物理请求数、快照、控制组
4 自然语言Gate 3 稳定后才可进行；只有与同次原始字节（含空白/Unicode 归一化）一致才算精确

§14.3 假设性演示 · 两点启示

若这段文本是隐藏推理

明确假设：Opus 4.8 的隐藏推理恰好是它这条真实输出 "failed. Let me try differently."（31 字符），且 thinking 已开、signature 保留、可 rehydrate。字母表 PRINTABLE_ASCII(97)，每字符 ⌈log₂97⌉=7 判定。
长度还原： 6 判定 × 3 票 × 2 = 36 请求 字符还原： 31 字符 × 7 × 3 × 2 = 1 302 请求 合计 ≈ 1 338 请求 → exact_match = True（须逐字节比对同次 ground truth）
启示一
攻击前提是「有加密推理状态且可 rehydrate」；真实 batch4 数据 reasoning_tokens=0，连原料都没有。
启示二
一旦前提成立，约 1338 个「只问是非」的请求即可在全程不触碰明文下逐字还原——这才是要用同次 ground truth 严格验证的核心主张。
§15 研究定位 · 属于哪一类工作

它坐落在三条公开研究脉络的交叉点

旁路信道
经典 side-channel 思路：秘密不从明文泄漏，而从时间 / 长度 / 资源占用等可观测量泄漏。本工具把「苦工量」写进状态长度，是 timing/length channel 的直接变体。
加密推理状态
厂商把 CoT 封进不透明状态（Claude thinking.signature / OpenAI encrypted_content）以隐藏推理。研究关心：这层封装是否真的不可观测。
CoT 蒸馏与防护
从强模型偷隐藏推理去蒸馏，是当前热点；防护方则研究如何让推理不可提取、不可复现。本工具是站在攻击面上的可证伪度量。
出处口径：以上是研究方向而非具体引用。对外引用前，每一篇论文 / 博客的标题、作者、结论都要逐条核实，不把方向当成已发表的既成事实。
§16 防御视角 · 服务方怎么堵

把攻击前提逐条拆掉

整条链依赖两个前提：① 服务端愿意 rehydrate 陌生 state；② 状态长度随私有推理量变化。防御就是把这两点各个击破。
攻击依赖防御动作
回灌任意 opaque state 都会被复活不 rehydrate 陌生 / 跨会话 / 跨请求的 state；state 与会话绑定 + 签名校验，拒绝 replay
状态长度随苦工量单调变化对返回状态做长度归一化 / 定长填充，让长短分支产生等长载体，抹掉长度差
同一 state 可被反复配对测量限制 signature 一次性 / 短时效，禁止同一 state 多次 replay
reasoning_tokens 精确可读用量字段分桶 / 加噪 / 不回传，切断第二条特征维度
成对差分抵消固定开销服务端注入随机延迟 / 随机 padding，抬高噪声底噪，压低 held-out AUC
最省事的一条：默认不开 extended thinking，就没有 signature，攻击面直接归零——正是 §14 batch4 真实数据里 reasoning_tokens=0 的天然状态。
